خطة الإشعارات الحقيقية عبر FCM

الهدف

نقل تنبيهات الصلاة والأذكار من مؤقت يعمل داخل صفحة التطبيق إلى Firebase Cloud Messaging، بحيث يمكن إرسال الإشعار حتى عندما لا تكون واجهة التطبيق مفتوحة. المرحلة الحالية لا تنفّذ FCM ولا ترسل أي إشعارات من خادم.

البنية المقترحة

1.
إضافة Firebase Cloud Messaging إلى تطبيق الويب وتهيئة Web Push certificate (VAPID) من إعدادات Firebase.

2.
طلب إذن الإشعارات بعد تفاعل واضح من المستخدم، ثم الحصول على FCM token وتخزينه داخل مستند المستخدم users/{uid}، مع دعم أكثر من جهاز عبر قائمة توكنات تحتوي على token, platform, timezone, updatedAt.

3.
إنشاء Cloud Function مجدولة تعمل على خطة Blaze. تقرأ المستخدمين الذين فعّلوا التنبيهات ولديهم موقع أو منطقة زمنية معروفة، ثم تحسب مواقيت اليوم من الإحداثيات وطريقة الحساب المحفوظة.

4.
جدولة الإرسال بحسب المنطقة الزمنية لكل مستخدم، مع منع التكرار باستخدام مفتاح يومي مثل uid + prayer + localDate، وحذف التوكنات التي يعيد FCM لها أخطاء عدم التسجيل أو عدم الصلاحية.

5.
إبقاء قواعد Firestore مانعة لقراءة توكنات المستخدمين من مستخدم آخر، والسماح للدالة عبر صلاحيات الخادم فقط. لا يجب وضع مفاتيح الخادم أو مفاتيح الخدمة في الواجهة.

6.
اختبار الإرسال على Chrome وAndroid PWA وSafari/Web Push مع حالات تغيير المنطقة الزمنية وإيقاف الإذن وتعدد الأجهزة.

متطلبات التشغيل والتكلفة

•
تشغيل Cloud Functions المجدولة يحتاج مشروع Firebase على خطة Blaze.

•
يجب ضبط حدود الإرسال والمراقبة والسجلات لتجنب الإرسال المكرر أو غير المقصود.

•
حتى بعد تنفيذ FCM، ينبغي عرض توضيح للمستخدم بأن الإشعار يعتمد على إذن النظام واتصال الجهاز وسياسات توفير الطاقة.
